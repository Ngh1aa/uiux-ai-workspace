# Design principles: <product>

3 to 5 principles that settle real arguments. Each one must be able to say **no** to something.
Write them after U1 (you know the users and top tasks), before visual direction.

| # | Principle | We choose... | ...over | Evidence / reason | Example decision it settled |
|---|---|---|---|---|---|
| P1 | Today first | What the parent must do today | Everything the centre wants to promote | T2 is daily, T1 is time-critical | Promotions moved off Home into Learning |
| P2 | Never lose a paid session | Recovery and confirmation | Fewer screens | T1 consequence is lost money | Review step kept on Move flow |
| P3 | | | | | |

Test each principle:

- Could a competitor's team say the opposite and still be reasonable? If not, it is a platitude ("easy to use"), cut it.
- Does it point to a specific screen or flow decision? If not, sharpen it.
- Is it about the user's outcome, not about the team's taste?
