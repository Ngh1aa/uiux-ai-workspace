## Scope classification

- Scope: `system`
- Type: `remediation + reliability hardening`
- Risk: `high`
- Mode: `production/reliability`

## Observed failure

`FACT`: a project can return a falsely green visual QA result when the test only inspects a small selector whitelist, does not render conditional populated states, or treats a guessed `object-position` as crop evidence.

The user-reported failure family includes:

- hover/focus label becoming light on a light surface;
- white/light text inherited onto a white/light summary/footer/surface;
- primary human/focal media cropped destructively by `object-fit: cover`;
- conditional CTA not exercised because test data kept the page empty.

## Root reliability gap

`FACT`: V5.4 already required computed-state contrast, shared-owner route coverage and human focal inspection, but it did not make the **coverage dimensions** explicit enough to prevent a project from claiming coverage while the broken state never rendered.

`EVIDENCE_BACKED_INFERENCE`: requiring route × viewport × data-state × interaction-state accounting, semantic/all-visible discovery and a default-block policy for unverified primary `cover` media materially reduces this false-green class.

## Reliability boundary

This hardening does not justify the absolute statement that a visual defect can never recur. It creates explicit, testable release blockers for this known failure class. A project that skips the required rendered/data/state verification can still fail operationally; such a skip must not be reported as a PASS.
