## Material changes

### 1. Failure diagnosis without a duplicate skill

**FACT:** existing `agent-evaluation-and-reliability` owns traces/reliability but did not have a focused repeated-run failure recovery workflow.

**Decision:** add a progressive reference rather than a new root skill.

Result:

```text
failure capture
→ classify logic/state/environment/policy/context/transient
→ build red-capable feedback loop
→ minimise
→ falsifiable hypotheses
→ contained recovery
→ rerun original repro
→ regression encode
```

### 2. Skill authoring becomes harder to game

Added:
- curation > collection for external sources;
- immutable source + license + overlap + context-cost decision record;
- optional common-rationalization/red-flag sections for real skip patterns;
- `new vs old` or `with vs without` skill comparisons for material behavior changes;
- outcome/tokens/context/duration/retry trade-off evaluation.

### 3. Review now has three independent axes

```text
A — requirement/spec fidelity
B — project/code standards
C — rendered/runtime evidence
```

A green axis cannot mask a failed axis. Build/tests cannot stand in for rendered evidence on a visual/runtime claim.

### 4. Runtime tool/observation contract

Added `runtime/TOOL-OBSERVATION-CONTRACT.md` defining:
- stable schema-first tool names;
- risk/authority/side-effect metadata;
- optional idempotent/open-world annotations;
- micro-tools for high-risk actions;
- structured `status / summary / next_actions / artifacts / data` observations;
- structured error `root_cause_hint / safe_retry / stop_condition`;
- context-efficient artifact references instead of log dumps.

### 5. Browser QA safety tightened

Playwright documentation now makes explicit:
- read-only default;
- no production checkout/payment/delete/mass-update testing;
- test credentials and evidence redaction;
- reconnaissance-before-action on dynamic apps;
- no visual baseline → `INCONCLUSIVE`, not PASS.

### 6. Skill discovery packaging

Added `scripts/build-skill-discovery-index.py`:
- scans root skills only;
- validates name/description;
- emits `.md` for single-file skills or deterministic `.tar.gz` for multi-file packages;
- emits SHA-256 digest + machine-readable `index.json`;
- does **not** publish releases or mutate install contracts.

Runtime validation smokes this builder in a temp directory.

## CI feedback and remediation

The first implementation run caught a validator defect: the new discovery smoke incorrectly required at least 100 root skills while the canonical current root count is 98.

**FACT:** `validate-skills.py` and `validate-v2.py` passed; only the new runtime discovery assertion failed on the arbitrary count threshold.

**Decision:** reject the count-as-quality proxy. The validator now derives the expected number from actual root directories containing `SKILL.md` and requires exact equality with the generated discovery index.

## Decision Log

### D-01 — No bulk vendor

**EVIDENCE_BACKED_INFERENCE:** importing whole upstream catalogs would increase ownership collision/context/provenance cost without proving local UI/UX value.

**Decision:** synthesize only capability gaps and keep immutable provenance.

### D-02 — Failure recovery is a progressive reference

**FACT:** it is adjacent to agent reliability/traces and would overlap heavily with the existing owner if made a root orchestrator.

**Decision:** reference under `agent-evaluation-and-reliability`.

### D-03 — Discovery first, publishing later

**FACT:** local consumers already have installers/version locks; changing distribution automatically is a separate release-contract decision.

**Decision:** build/validate deterministic artifacts now; keep auto-publish `N/A_JUSTIFIED`.

### D-04 — No generic browser mutation

**FACT:** browser automation can mutate real accounts/data even though the automation surface appears to be “QA”.

**Decision:** read-only by default; staging/test data + explicit authority for mutations.

### D-05 — No arbitrary skill-count quality threshold

**FACT:** the current root package count is 98, while the first discovery smoke assumed 100 as a minimum.

**Decision:** verify completeness against project truth (actual root skill packages), not an arbitrary quantity threshold.
