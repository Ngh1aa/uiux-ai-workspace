## Incident trigger

A real multi-page implementation passed prior QA while still containing elementary rendered defects:

- shared light footer with near-white text that became readable only after text selection;
- outlined/light CTA whose label disappeared in an interaction state because foreground and surface no longer matched;
- a checkout CTA whose more-specific inherited link color created an effective `1:1` label/background pair;
- a hero `cover` crop that cut the model's head.

The existing library already mentioned contrast, states, rendered inspection and focal points, but the process still allowed skip behavior because those rules were not expressed as a single mandatory elementary sanity gate with shared-owner coverage and a regression promotion requirement.

## Decision log

### D-01 — Extend existing owners, do not create a new skill

- Label: `FACT`
- Evidence: the relevant capability boundaries already belong to visual QA, design system, media, testing and visual regression.
- Decision: extend these owners and add one progressive checklist instead of creating a mostly-overlapping new skill.
- Impact: smaller routing graph; stronger existing gates.

### D-02 — Separate representative deep review from all-route elementary sanity

- Label: `EVIDENCE_BACKED_INFERENCE`
- Problem: representative page sampling is appropriate for deep visual judgment but can miss/reclassify a shared owner defect as already covered.
- Decision: shared header/footer/nav/theme/button/surface changes require elementary sanity on every affected route/template; deep aesthetic review may remain representative.
- Impact: site-wide cascade defects cannot be considered verified from one sample route.

### D-03 — Computed render beats intended CSS

- Label: `FACT`
- Decision: source declaration is not evidence when browser cascade/specificity can produce a different computed foreground/background.
- Impact: fixes must inspect winning style and root owner; page-local override chains are discouraged.

### D-04 — Human focal crop is a hard visual gate

- Label: `FACT`
- Decision: `object-fit: cover`/`object-position` are implementation choices, not proof. Human/primary subject crops must be inspected at declared viewports.
- Impact: unjustified face/head clipping blocks visual handoff.

## Reliability boundary

These changes materially reduce recurrence risk and make the failure mode explicit/testable. They do **not** create a mathematical guarantee that no future implementation can ever violate contrast/crop rules. Reliability still depends on the project/agent actually running the required rendered verification. The library now forbids claiming PASS when that due-now evidence is skipped.
