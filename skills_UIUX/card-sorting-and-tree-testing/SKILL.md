# Card Sorting & Tree Testing

## Workflow
1. Identify representative content/items and participant groups.
2. Use card sorting when grouping or labels are uncertain.
3. Synthesize clusters and participant language without blindly averaging.
4. Draft hierarchy and navigation labels.
5. Use tree testing with realistic findability tasks and no visual UI cues.
6. Analyze success paths, wrong branches, hesitation and confidence.
7. Revise hierarchy and retest important destinations.

## Rules
- Card sorting generates evidence; it does not automatically produce the final sitemap.
- Tree testing evaluates findability, not visual design.
- Keep tasks destination-focused and avoid using exact menu labels in task wording.

## Quality gate
High-value destinations have evidence of findability and labels reflect user language unless business/legal constraints justify otherwise.
