# Design System Governance & Adoption

## Workflow
1. Define criteria for new component vs variant vs local composition.
2. Assign ownership and contribution review.
3. Track component maturity, accessibility and test status.
4. Version/deprecate with migration guidance.
5. Audit duplicate patterns and token drift.
6. Measure adoption and exceptions.
7. Document intentional escape hatches.

## Quality gate
No duplicate component without gap analysis; breaking changes have migration paths; deprecated APIs are discoverable; system health includes usage and accessibility, not component count.
