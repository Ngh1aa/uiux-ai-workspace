# Mobile design handoff review

- [ ] Requested output, platforms, OS range and stack are explicit; unknowns remain visible.
- [ ] Current baseline/source/design revision and preserved brand/components are identified.
- [ ] One screen/state inventory and navigation graph cover primary tasks and relevant recovery.
- [ ] iOS/Android differences, keyboard/insets, touch units and text scaling are specified.
- [ ] Existing tokens/components are reused; additions have a purpose and state/semantics contract.
- [ ] Adopted sources have URLs, immutable code refs where applicable, licenses and decision links.
- [ ] Real/mock/simulated data, prototype limitations and device integrations are labelled.
- [ ] Design captures are inspected; issues have severity, evidence, owner and retest state.
- [ ] Native runtime, assistive technology, performance, human research and release claims do not exceed evidence.
- [ ] File-integrity receipts are not treated as visual quality or approval.
- [ ] Paid/cloud services, Figma mutation and store submission respect existing authorization.
