# Information Architecture Quality Gate

Use before approving a sitemap/navigation restructure.

## Evidence
- [ ] Primary audiences/tasks are identified.
- [ ] Entry contexts include deep links/search-engine landings, not only homepage.
- [ ] Research/analytics assumptions are labeled honestly.
- [ ] High-risk IA decisions have a validation plan or evidence.

## Inventory
- [ ] Important content and functionality are inventoried.
- [ ] Legacy content is classified keep/improve/merge/split/move/retire for redesigns.
- [ ] Owners/sources are known for high-value content.

## Taxonomy and labels
- [ ] Categories reflect user task/topic mental models where appropriate.
- [ ] Sibling categories are meaningfully distinct.
- [ ] Labels have strong information scent.
- [ ] Internal jargon and vague umbrella terms are minimized.
- [ ] Synonyms/aliases are considered for search and multilingual contexts.
- [ ] Legitimate cross-listing/polyhierarchy is used without duplicating canonical content.

## Hierarchy
- [ ] Breadth/depth decisions have a rationale.
- [ ] No arbitrary 3-click rule is used.
- [ ] No 7±2 menu-item myth is used.
- [ ] Intermediate pages add orientation/decision value.
- [ ] Deep structures provide shortcuts or orientation mechanisms.

## Page roles
- [ ] Every important page has a clear role.
- [ ] Hub/category pages expose useful choices.
- [ ] Destination pages answer specific needs.
- [ ] Task pages support completion/recovery.
- [ ] Empty gateway pages are removed or justified.

## Navigation and findability
- [ ] Global, local, utility and contextual navigation responsibilities are clear.
- [ ] Search/filter is considered when the information space warrants it.
- [ ] Breadcrumbs/orientation are considered for deep/complex structures.
- [ ] High-value destinations have resilient paths.
- [ ] Desktop/mobile labels remain semantically consistent.
- [ ] Link text predicts destination adequately.

## URL and migration
- [ ] URL structure is stable and descriptive.
- [ ] Existing high-value routes are preserved or redirected.
- [ ] Canonical/redirect decisions align with SEO strategy.
- [ ] Internal links can be migrated without orphaning content.

## Validation
- [ ] Card sorting is not treated as the final sitemap.
- [ ] Tree testing is used when category/findability risk is material.
- [ ] Usability testing covers important navigation tasks when feasible.
- [ ] Search logs/support data are considered for vocabulary/content gaps.

## Accessibility
- [ ] Navigation structure remains understandable with semantic markup.
- [ ] Users have clear orientation and recovery routes.
- [ ] Important destinations are not dependent on hover-only discovery.
- [ ] Navigation order and labels are consistent enough for assistive technology users.

## Final consistency
- [ ] Sitemap, page inventory, page roles and navigation model agree.
- [ ] IA supports the project's primary journeys and conversion/task goals.
- [ ] Known risks and unresolved decisions are documented.
