# Entry Context & Visit Intent

## Principle
The homepage is only one entrance. Every important page may be an entry page.

`source → query/message → landing context → user expectation → orientation → next best action`

## Workflow
1. List realistic entry sources: organic search, paid campaign, social, email, partner/referral, QR/offline, direct/bookmark, internal link, returning authenticated visit.
2. For each source, record likely intent and prior knowledge.
3. Check message match between what brought the user in and what the landing page immediately communicates.
4. Give users rapid orientation: where am I, what is this, is this relevant to me, what can I do next?
5. Preserve context across navigation, filters, forms and return visits when useful.
6. Design deep pages so they do not depend on the user having read the homepage first.

## Entry-state matrix
For important entry pages capture:
- source/query/referral;
- user goal;
- expected answer;
- confidence needed;
- primary action;
- alternate path;
- recovery if wrong destination.

## Analytics hooks
Where analytics exists, compare:
- landing page;
- acquisition source/query/campaign;
- task completion/conversion;
- pogo/back behavior;
- internal search after entry;
- next-page path.

## Required artifact
`docs/entry-intent-map.md` for large or acquisition-heavy sites.

## Gate
A deep-linked user should understand the page and continue their task without needing to return to the homepage for orientation.

## Anti-patterns
- Designing every journey from homepage downward.
- Generic landing pages that ignore campaign/search intent.
- Removing navigation/context on SEO pages purely for conversion pressure.
- Resetting useful user context after every page transition.
