# Service Blueprinting

## Workflow
1. Define service outcome and start/end boundaries.
2. Map user actions across digital and relevant offline channels.
3. Add frontstage interactions and support touchpoints.
4. Add backstage people, processes, systems and data dependencies.
5. Mark handoffs, waits, failure points and ownership gaps.
6. Separate UI problems from service/operational problems.
7. Prioritize opportunities by user and operational impact.

## Quality gate
- Critical handoffs have ownership.
- Offline/support steps are not ignored.
- UI is not used to disguise a broken backstage process.
- Blueprint identifies evidence gaps that need research.
