# Blueprint Gate

Each item is pass or fail.

- [ ] Scenario, start trigger and user-meaningful end state are stated.
- [ ] Canvas is declared as-is or to-be, not both.
- [ ] All lanes are present: evidence, customer, frontstage, backstage, support, with the three lines.
- [ ] Offline and support steps in the scenario are included.
- [ ] Every user action has an evidence artifact or an E? marker.
- [ ] Every backstage and support item names an owning role or team.
- [ ] Every critical handoff names sender and receiver; missing receivers are logged as ownership gaps.
- [ ] Every wait shows an observed range or is tagged assumed.
- [ ] Every fail point records detection and recovery.
- [ ] Each pain point is classified UI, service or policy.
- [ ] No UI mitigation hides a broken process without an operational owner logged.
- [ ] Assumed cells are listed as research gaps with a verification method.
- [ ] At least one backstage practitioner reviewed the as-is blueprint.
