# Journey-Driven Content & Layout

## Principle
Do not map `content item → block`. Map `user state → question → answer → evidence → next question/action`.

A page should create decision momentum, not merely display available content.

## Workflow
### 1. Define page role
Orientation, exploration, comparison, evaluation, transaction, confirmation or recovery.

### 2. Identify user state on arrival
What do they already know? What question is unresolved? What risk blocks progress?

### 3. Build question sequence
Typical progression may include:
- What is this?
- Is it relevant to me?
- What can I do/get here?
- Why should I trust it?
- What is the experience like?
- What does it cost/require?
- What are my alternatives?
- What happens next?

Use the project's actual journey rather than this template when evidence exists.

### 4. Map each section to a job
Each section must have one primary job: orient, explain, demonstrate, prove, compare, reduce risk, enable action or transition.

### 5. Order for progressive confidence
Move from relevance to understanding to evidence to decision. Surface critical information early when users need it early.

### 6. Design transitions
End each major section with a logical bridge into the user's next question or action, not arbitrary visual rhythm.

## Section contract
For each section document:
- user state/question;
- section job;
- key content/evidence;
- visual treatment rationale;
- CTA or transition;
- what should be true after viewing it.

## Gate
Remove any section that cannot explain which user question or decision it advances.

## Anti-patterns
- Hero → logo strip → 3 cards → features → news → CTA by habit.
- Mirroring the organization chart.
- Putting all proof at the bottom regardless of user doubt.
- Repeating the same message in multiple decorative sections.
- Optimizing scroll aesthetics while losing decision clarity.
